# Job Interview Assistant

A **Python** demo app: an AI-powered mock interview built with **Streamlit** and **Google Gemini**. The whole experience is implemented in a single Python script (`app.py`); Streamlit turns that into the web UI. The app simulates a short structured interview tailored to profile fields you enter, then generates a concise score and written feedback based on the full transcript.

---

## Live demo

**Deployed on Streamlit Cloud:** [https://job-interview-assistant-ai.streamlit.app/](https://job-interview-assistant-ai.streamlit.app/)

This repository is intentionally a **demo / learning project**. It is not a production HR product: there is no persistent user database, guarantees about AI behavior, compliance review, or human oversight. Responses are generated by an external LLM and may be inaccurate or inappropriate—use for practice only.

## Technology stack

The project is **Python-first**: you run it with the CPython interpreter (`python` / `streamlit run`), and dependencies are installed with **pip** from `requirements.txt`.

| Layer | Choice | Role in this project |
|--------|--------|----------------------|
| **Language** | **Python 3** | All application logic, LLM calls, and UI flow in `app.py` |
| **UI framework** | [Streamlit](https://streamlit.io/) | Single-file web app: forms, chat, streaming text, session state, secrets |
| **LLM SDK** | [google-genai](https://pypi.org/project/google-genai/) (Google Gen AI SDK for Python) | Authenticated calls to **Gemini** (`Client`, `generate_content_stream`, `types.GenerateContentConfig`, etc.) |
| **Browser helper** | [streamlit-js-eval](https://pypi.org/project/streamlit-js-eval/) | Runs a tiny JavaScript snippet to **reload the parent window** after “Restart Interview” so session state resets cleanly |

### Libraries (from `requirements.txt`)

| Package | Version constraint | Purpose |
|---------|-------------------|---------|
| `streamlit` | `>=1.28.0,<1.51` | Web UI, `st.session_state`, `st.chat_message`, `st.write_stream`, secrets, widgets |
| `google-genai` | `>=1.0.0,<1.48` | Official client for Gemini: streaming generation, system instructions, error types |
| `streamlit-js-eval` | `>=0.1.5` | `streamlit_js_eval(js_expressions="parent.window.location.reload()")` for full page refresh |

**Transitive dependencies** (installed automatically) include HTTP clients, auth, and retry logic used by `google-genai` (for example `httpx`, `tenacity`, Google auth libraries). You do not pin those in this repo; they come with the SDK.

## How the app works

Streamlit **reruns the entire script** on every interaction. The app uses **`st.session_state`** as in-memory state for the current browser session (lost on refresh unless you add persistence).

### Phase 1 — Setup

1. User enters **personal information** (name, experience, skills) and **job context** (seniority, role, company) via text fields and selectors.
2. **Start Interview** sets `setup_complete = True`.

A **system instruction** is built from these fields: the model is told to act as an HR interviewer for that person and role at that company.

### Phase 2 — Interview chat

1. The conversation is stored as a list of dicts: `{ "role": "user" | "assistant", "content": "..." }` (UI uses Streamlit’s `assistant` label; when calling Gemini, assistant turns are mapped to API role **`model`**, as required by the Gemini API).
2. For the **first four** user messages, the app calls **`generate_content_stream`**: prior turns are sent as `types.Content` history, the new user message is appended, and tokens are streamed into the chat with **`st.write_stream`**.
3. On the **fifth** user message, the app **does not** request another model reply; it only records the user’s message and marks the interview as structurally complete (`user_message_count >= 5` → `chat_complete`).
4. API failures during streaming are caught (`google.genai.errors.APIError`): the last user message is rolled back so the user can retry, and an error is shown in the UI.

### Phase 3 — Feedback

1. After the interview is complete, the user clicks **Get Feedback**.
2. The full transcript is flattened to a string and sent in one user turn, with a separate **feedback system prompt** (score 1–10, fixed output format, no follow-up questions).
3. The response is streamed, stored in `st.session_state["feedback_body"]`, and shown on subsequent rerenders.
4. **Restart Interview** triggers a **full browser reload** via `streamlit-js-eval` so all session state resets for a new run.

## Configuration and secrets

### Streamlit Cloud

In the app settings, define **Secrets** (TOML), for example:

```toml
GEMINI_API_KEY = "your-api-key"
GEMINI_MODEL = "gemini-2.0-flash"
```

Use a model id that your key is allowed to call in [Google AI Studio](https://aistudio.google.com/) (or your Google Gen AI setup). The exact string must match what the API expects (e.g. `gemini-2.0-flash`, `gemini-1.5-flash`, etc.).

### Local development

1. Create a virtual environment and install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

2. Add `.streamlit/secrets.toml` (do **not** commit real keys; keep this file out of version control or use placeholders):

   ```toml
   GEMINI_API_KEY = "your-api-key"
   GEMINI_MODEL = "gemini-2.0-flash"
   ```

3. Run:

   ```bash
   streamlit run app.py
   ```

## Limitations (demo scope)

- **No authentication** — anyone with the URL can use the deployed app (subject to Streamlit and your API quotas).
- **No server-side storage** of interviews; state lives in the session until reload.
- **Fixed flow** — four assistant replies, then a fifth user message without a final model turn in the main chat, then optional feedback.
- **LLM risks** — hallucinations, bias, and policy edge cases are possible; this is not a substitute for real interview preparation services or hiring decisions.
